# CLAUDE.md

## Что это

Meal Planner & Recipes — macOS-приложение: рецепты с КБЖУ, база продуктов, запасы дома, список покупок и меню на неделю. Данные доступны Claude Desktop и Claude Code через MCP. Готовы этапы 0 (каркас), 1 (продукты и единицы) и 2 (рецепты и категории).

- Замысел, решения и этапы — [plan-meal-planner.md](plan-meal-planner.md). Решения оттуда не пересматриваем без явной просьбы; новое решение сначала вносим в план.

## Команды

| Команда | Что делает |
|---|---|
| `make project` | Генерирует `MealPlanner.xcodeproj` из `project.yml` (XcodeGen) |
| `make build` | Debug-сборка приложения и MCP-утилиты (по умолчанию для `make`) |
| `make test` | `swift test` для пакета, затем тесты приложения через `xcodebuild` |
| `make test-package` | Только тесты `MealKit`: быстро, без Xcode-проекта |
| `make run` | Собрать и запустить Debug-версию |
| `make install` | Release-сборка в `/Applications` — нужна для постоянного пути MCP-сервера |
| `make mcp-inspect` | MCP Inspector для встроенного `meal-planner-mcp` |
| `make format` / `make lint` | `swift-format` из тулчейна, настройки — в `.swift-format` |
| `make perf` | Бюджет списков в оптимизированной сборке на 20 000 продуктов и 5 000 рецептов: первый блок быстрее 50 мс, поиск и сортировка быстрее 100 мс |
| `make seed USDA=<папка>` | Пересобрать начальную базу продуктов из `Tools/seed/catalog.py` и USDA SR Legacy (CSV) |
| `make clean` | Удалить `build/` и `.build/` пакета |

`.xcodeproj` не хранится в git. После правки `project.yml`, добавления или удаления файлов — `make project`. Настройки сборки меняем только в `project.yml`: правки в интерфейсе Xcode сотрёт следующая генерация. Сборки из терминала лежат в `build/DerivedData`.

## Структура и границы модулей

- `Apps/MealPlanner` — SwiftUI-приложение: окно, экраны, связь с macOS. Здесь только интерфейс, логика — в пакете. Папки:
  - `App` — точка входа, `AppModel`, `Formatting`, `Thumbnails` (миниатюры фото, цвета тегов);
  - `Window` — окно с боковой панелью разделов и категорий;
  - `Screens/Lists` — общие части списков: чипы фильтров, диапазоны, ячейки, выбор продукта;
  - `Screens/Products` — экран продуктов;
  - `Screens/Recipes` — галерея, таблица КБЖУ, фильтры, корзина;
  - `Screens/Recipe` — страница рецепта и её редактор, ингредиенты, фото, видео и превью ссылок;
  - `Settings`, `Resources` (`Assets.xcassets` с цветовыми токенами, `Localizable.xcstrings`).
- `Apps/MCPServer` — точка входа `meal-planner-mcp`; утилита встраивается в `MealPlanner.app/Contents/Helpers/`.
- `Apps/MealPlannerTests` — тесты, которым нужен собранный бандл приложения.
- `Packages/MealKit` — вся логика:
  - `MealCore` — модели и логика: единицы и пересчёты (`MeasureUnit`, `UnitProfile`), КБЖУ (`Nutrition`, `NutritionTotal`, `RecipeNutrition`), продукт и рецепт (`RecipeDetails`), разбор строк ингредиентов (`IngredientParser`), видео (`VideoEmbed`), поиск (`SearchText`, `RussianStemmer`), запросы списков (`ProductQuery`, `RecipeQuery`, `SortTerm`, `ListPage`), общие имена (`AppIdentity`). Только Foundation: без AppKit, SwiftUI и GRDB.
  - `MealStore` → `MealCore`, GRDB: схема, миграции, начальная база (`Seed/`), запросы списков в SQL, кеш рецептов (`RecipeDerived`), фото (`ImageStore`), `PagedList`.
  - `MealMCP` → `MealCore`, `MealStore`, MCP SDK: инструменты для Claude.
  - `MealReminders` (EventKit) появится на этапе 6.
- `Tools/seed` — каталог начальной базы и её сборка.

## Подпись и идентификаторы

- Команда `6S43T3N4UL` — та же, что у Portion и Market Monitor; подпись автоматическая. `xcodebuild` запускается с `-allowProvisioningUpdates` (уже в Makefile).
- Название для людей — «Meal Planner & Recipes» (`AppIdentity.displayName`, `CFBundleDisplayName`). Цели сборки, бандл и файлы называются `MealPlanner` — без «&» и пробелов.
- Bundle ID: приложение `inco.mealplanner.app` (Debug — `inco.mealplanner.app.debug`), MCP-утилита `inco.mealplanner.mcp`, тесты `inco.mealplanner.app.tests`. URL-схема `mealplanner` (Debug — `mealplanner-debug`).
- Песочница выключена, Hardened Runtime включён. Минимальная macOS — 26.0.

## Правила кода

- Swift 6 со строгой проверкой конкурентности: модели `Sendable`, интерфейс — `@MainActor`.
- Тесты — Swift Testing (`import Testing`). Код ядра попадает в коммит только вместе с тестами.
- Компилятор и `make lint` — без предупреждений.
- Тексты интерфейса — по-русски; комментарии в коде — по-английски.
- Числа в интерфейсе — через `Formatting`: русская десятичная запятая при любом регионе Mac.
- Логи — `os.Logger` с subsystem `inco.mealplanner`.
- MCP-сервер пишет в stdout только протокол; диагностика — в stderr или `os.Logger`.

## Интерфейс и тема

- Тема тёмная: `AppDelegate` ставит `NSApp.appearance = .darkAqua` до первого кадра, поэтому тёмные и окна, и меню, и алерты, и Настройки.
- Цвета — только токены из `Assets.xcassets` через сгенерированные символы: `Color(.canvas)`, `Color(.textSecondary)`… Цветовых литералов в коде нет. Пока у каждого токена одно значение — тёмное; светлая тема добавит к тем же токенам светлый вариант.
- Токены: `Canvas` (фон окна), `Surface`, `SurfaceRaised`, `Card`, `Hairline`, `TextPrimary`, `TextSecondary`, `StatusInStock` / `StatusLow` / `StatusMissing`, `AccentColor`, цвета тегов `TagGray` … `TagRed` — палитра Notion для категорий и приёмов пищи (`TagColor.color`, `TagView`).
- Склейка `Text + Text` в macOS 26 устарела — стиль части строки задаём интерполяцией: `Text("\(Text("Отдел:").foregroundStyle(…)) \(value)")`.
- Перестановка перетаскиванием — `.draggable(id.uuidString)` и `.dropDestination(for: String.self)` на строке: `onMove` работает только в `List`.

## Единицы и КБЖУ

- У продукта есть основная единица (`BaseUnit`: г, мл или шт.) — в ней живут запасы и покупки. Пересчёт — `UnitProfile`: внутри массы и внутри объёма по таблице, иначе через граммы (вес штуки, плотность, вес именованных единиц вроде зубчика или пучка).
- Ложки и стакан — ровные метрические меры: ч. л. = 5 мл, ст. л. = 15 мл, стакан = 250 мл.
- Чего продукт не знает, того не угадываем: пересчёт возвращает `nil`, интерфейс показывает «?».
- КБЖУ хранится на 100 г. `NutritionTotal` складывает ингредиенты и считает, сколько из них удалось учесть. Диапазон «2–3» считается по середине; строки без количества («по вкусу») в полноту не входят.

## Рецепты

- Рецепт целиком — `RecipeDetails`: сам рецепт, строки ингредиентов, шаги, категории, приёмы пищи и продукты, на которые ссылаются строки. `save(_:)` записывает его целиком в одной транзакции: строки и шаги заменяются, пустые шаги отбрасываются. У строк и шагов id живут только в памяти.
- КБЖУ рецепта — `RecipeNutrition`: на 100 г по весу готового блюда, если он задан, иначе по сырым продуктам; на порцию — сумма, делённая на порции. Значения с сайта (`nutritionOverride`) заменяют расчёт. Неполный расчёт не обнуляется: списки показывают его с «≈», страница — «посчитано по N из M» и чего не хватило.
- `recipe_stats` — кеш для списков: КБЖУ, время, текст для поиска (название, шаги, заметки, продукты с синонимами). Его пересчитывает `RecipeDerived.refresh` в той же транзакции, что меняет рецепт или его продукт: сохранение рецепта, сохранение и объединение продукта. Любой новый способ записи, задевающий рецепт или продукт, обязан его вызвать.
- Продукт из рецепта удалить нельзя (внешний ключ `RESTRICT` и понятное сообщение); при объединении дублей строки рецептов переходят на оставшийся продукт.
- Корзина: `deletedAt`; списки и счётчики её не видят; при запуске удаляется то, что лежит дольше 30 дней, вместе с фото.
- Фото — `ImageStore`: JPEG до 1600 px по длинной стороне в папке `Images` рядом с базой; в базе только имя файла. У каждого рецепта своё фото (дубликат копирует файл); заменённое фото удаляется после сохранения, а файлы без рецепта старше часа — при запуске.
- Видео — `VideoEmbed`: YouTube (плеер youtube-nocookie), Rutube, VK Видео, любой `<iframe>`. Плеер грузится в WKWebView через `loadHTMLString` с https-адресом страницы: без него YouTube показывает «Ошибка 153». Ссылки — карточками LinkPresentation.
- Галерея: строка запроса — пара «категория — рецепт», поэтому рецепт из двух категорий виден в обеих; группы появляются по мере подгрузки; свёрнутые группы исключаются в SQL, но их счётчики остаются.

## Поиск, фильтры и сортировка

- Запрос экрана — тип в `MealCore` (`ProductQuery`, `RecipeQuery`): текст, фильтры, сортировка. `MealStore` переводит его в SQL (`ProductListSQL`, `RecipeListSQL`); тот же запрос получат и MCP-инструменты.
- Поиск — FTS5-таблицы `product_ft` (по `product.searchText`) и `recipe_ft` (по `recipe_stats.searchText`). `searchText` и `nameKey` продукта пишет `ProductRecord` при каждом сохранении, поэтому имя и синонимы меняем только через него, а не сырым SQL.
- Запрос разбивается на основы слов (`SearchText.terms`: регистр и «ё» не важны, окончания режет стеммер Snowball), каждая ищется как префикс; все слова должны совпасть.
- При поиске полнотекстовая выборка — внешний цикл (`CROSS JOIN`): иначе SQLite повторяет её для каждой строки из индекса, и запрос с фильтрами замедляется в 30 раз.
- Порядок всегда заканчивается названием и id — равные значения не прыгают между блоками. Пустые значения — в конце при любом направлении.
- Списки грузятся блоками по 100 строк (`PagedList`): `ValueObservation` следит за `LIMIT n`, строка за 20 до конца загруженного добавляет следующий блок, новый запрос начинает с первого.

## Начальная база

- Каталог — `Tools/seed/catalog.py`: название, синонимы, отдел, источник КБЖУ (номер записи USDA FDC или типичные значения с упаковки), единицы. `make seed USDA=<папка с CSV SR Legacy>` собирает его в `Packages/MealKit/Sources/MealStore/Seed/SeedCatalog+Data.swift` — JSON внутри Swift-строки, потому что ресурсы SwiftPM недоступны MCP-утилите внутри приложения. Сгенерированный файл руками не правим.
- Значения USDA берём как опубликованы; калории проверяем по коэффициентам USDA для этого продукта, остальные — по 4·Б + 9·Ж + 4·У (`SeedCatalogTests`, тот же расчёт — в `build.py`).
- Начальная база — это миграция `seed: products 1`: загружается один раз, удалённое пользователем не возвращается. Новые продукты в базе — новая миграция только с ними.

## Разбор ингредиентов

- `IngredientParser` читает строки, как их пишут русские рецепты: количество (цифры, дроби, «½», диапазоны, «полтора», «пол-»), единица во всех формах, название, заметки в скобках, «по вкусу», «по желанию», «для жарки».
- Каждый новый случай — строка в `IngredientParserTests`; сейчас их 80.
- В редакторе рецепта строка ищет продукт по имени и синонимам; если такого нет — предлагает создать, и название можно поправить: в рецепте оно бывает в другом падеже («феты»).

## Хранилище и данные

- База — `AppDatabase` (GRDB): `~/Library/Application Support/inco.mealplanner/meals.sqlite`, у Debug — папка `inco.mealplanner.debug`. И приложение, и MCP-сервер пишут через `DatabasePool` (WAL) с ожиданием блокировки до 5 секунд.
- Схема меняется только новой миграцией в `AppDatabase.migrator`; уже применённые миграции не редактируем. Сейчас: `products`, `seed: products 1`, `recipes`.
- `AppDatabase.inMemory()` — пустая база для тестов (фото — во временной папке), `inMemory(seeded: true)` — с начальной базой.

## MCP

- Сервер `meal-planner` (`MealMCPServer`), транспорт stdio. Без аргументов внутри бандла работает с данными своего приложения (Debug — со своими); `--directory <папка>` — с указанной.
- Пока есть один инструмент — `get_status`, и он не создаёт базу, если её ещё нет. Инструменты для рецептов и продуктов появятся на этапе 3.
- Новый инструмент: определение в `MealTools.all`, ветка в `MealTools.call`, тесты в `MealMCPTests`. `PackagingTests` проверяет, что встроенный в бандл сервер отвечает по stdio.
- До этапа 3 сервер подключается к Claude вручную — см. README.
