# CLAUDE.md

## Что это

Meal Planner & Recipes — macOS-приложение: рецепты с КБЖУ, база продуктов, запасы дома, список покупок и меню на неделю. Данные доступны Claude Desktop и Claude Code через MCP. Готовы этапы 0 (каркас), 1 (продукты и единицы), 2 (рецепты и категории), 3 (MCP и Claude), 4 (запасы и покупки), 5 (меню на неделю) и 6 («Напоминания» и «Поделиться»).

- Замысел, решения и этапы — [plan-meal-planner.md](plan-meal-planner.md). Решения оттуда не пересматриваем без явной просьбы; новое решение сначала вносим в план.

## Команды

| Команда | Что делает |
|---|---|
| `make project` | Генерирует `MealPlanner.xcodeproj` из `project.yml` (XcodeGen) |
| `make build` | Debug-сборка приложения и MCP-утилиты (по умолчанию для `make`) |
| `make test` | `swift test` для пакета, затем тесты приложения через `xcodebuild` |
| `make test-package` | Только тесты `MealKit`: быстро, без Xcode-проекта |
| `make run` | Собрать и запустить Debug-версию |
| `make install` | Release-сборка в `/Applications` — нужна для постоянного пути MCP-сервера |
| `make mcp-inspect` | MCP Inspector для встроенного `meal-planner-mcp` |
| `make format` / `make lint` | `swift-format` из тулчейна, настройки — в `.swift-format` |
| `make perf` | Бюджет списков в оптимизированной сборке на 20 000 продуктов и 5 000 рецептов: первый блок быстрее 50 мс, поиск и сортировка быстрее 100 мс |
| `make seed USDA=<папка>` | Пересобрать начальную базу продуктов из `Tools/seed/catalog.py` и USDA SR Legacy (CSV) |
| `make clean` | Удалить `build/` и `.build/` пакета |

`.xcodeproj` не хранится в git. После правки `project.yml`, добавления или удаления файлов — `make project`. Настройки сборки меняем только в `project.yml`: правки в интерфейсе Xcode сотрёт следующая генерация. Сборки из терминала лежат в `build/DerivedData`.

## Структура и границы модулей

- `Apps/MealPlanner` — SwiftUI-приложение: окно, экраны, связь с macOS. Здесь только интерфейс, логика — в пакете. Папки:
  - `App` — точка входа, `AppModel`, `Formatting`, `Thumbnails` (миниатюры фото, цвета тегов);
  - `Window` — окно с боковой панелью разделов и категорий;
  - `Screens/Lists` — общие части списков: чипы фильтров, диапазоны, ячейки, выбор продукта;
  - `Screens/Products` — экран продуктов;
  - `Screens/Recipes` — галерея, таблица КБЖУ, фильтры, корзина;
  - `Screens/Recipe` — страница рецепта и её редактор, ингредиенты с наличием дома, фото, видео и превью ссылок, «Поделиться» (`ShareCard`: карточка-картинка через `ImageRenderer` и текст, `NSSharingServicePicker`);
  - `Screens/Planner` — меню на неделю: сетка, ячейки и карточки блюд (`PlanCell`, перетаскивание — `PlanDragItem` с типом `inco.mealplanner.plan-item` из Info.plist), рецепты сбоку (`PlannerLibrary`), «Приготовлено» (`CookedSheet`);
  - `Screens/Pantry`, `Screens/Shopping` — запасы и список покупок; общие части — `Lists/QuickAddField` (строка «яйца 10», поле количества, группы по отделам);
  - `System` — связь с Claude: конфиг Claude Desktop (`ClaudeConnection`), кнопки «… с Claude» (`ClaudeHandoff`), папка с CLAUDE.md для сессий Claude Code (`ClaudeWorkspace`); синхронизация с «Напоминаниями» (`RemindersModel`);
  - `Settings`, `Resources` (`Assets.xcassets` с цветовыми токенами, `Localizable.xcstrings`).
- `Apps/MCPServer` — точка входа `meal-planner-mcp`; утилита встраивается в `MealPlanner.app/Contents/Helpers/`.
- `Apps/MealPlannerTests` — тесты, которым нужен собранный бандл приложения.
- `Packages/MealKit` — вся логика:
  - `MealCore` — модели и логика: единицы и пересчёты (`MeasureUnit`, `UnitProfile`), КБЖУ (`Nutrition`, `NutritionTotal`, `RecipeNutrition`), продукт и рецепт (`RecipeDetails`), разбор строк ингредиентов (`IngredientParser`), видео (`VideoEmbed`), поиск (`SearchText`, `RussianStemmer`), запросы списков (`ProductQuery`, `RecipeQuery`, `SortTerm`, `ListPage`), общие имена (`AppIdentity`), запросы к Claude (`ClaudeRequest`: тексты промптов MCP и кнопок «… с Claude»), запасы и покупки (`Pantry.swift`: `PantryItem`, наличие строки рецепта `Availability`, нехватка `ShoppingAddition`, `ShoppingItem`, запросы `PantryQuery` и `ShoppingQuery`), меню (`Planner.swift`: день `Day`, блюдо `PlanEntry`, неделя `WeekPlan` с КБЖУ дня и распределением запасов `MenuSupply`, списание `CookingUse`). Только Foundation: без AppKit, SwiftUI и GRDB.
  - `MealStore` → `MealCore`, GRDB: схема, миграции, начальная база (`Seed/`), запросы списков в SQL, кеш рецептов (`RecipeDerived`), фото (`ImageStore`), `PagedList`, уведомления о записи из другого процесса (`ExternalChanges`), запасы и покупки (`Pantry+Store`, `Shopping+Store`, списки — `PantryListSQL`, `ShoppingListSQL`), меню (`Planner+Store`).
  - `MealMCP` → `MealCore`, `MealStore`, MCP SDK: инструменты (`MealTools` и расширения `ProductTools`, `CategoryTools`, `RecipeTools`, `PantryTools`, `PlannerTools`), разбор аргументов (`Arguments`), вид ответов (`ToolOutput`), промпты (`MealPrompts`).
  - `MealReminders` → `MealCore`, `MealStore`, EventKit: синхронизация списка покупок с «Напоминаниями» (`ShoppingSync`), настройки и вид пунктов (`ReminderSettings`, `ReminderText`), хранилище — протокол `ReminderStore`, на Mac `EventKitReminderStore`, в тестах подделка.
- `Tools/seed` — каталог начальной базы и её сборка.

## Правила кода

- Swift 6 со строгой проверкой конкурентности: модели `Sendable`, интерфейс — `@MainActor`.
- Тесты — Swift Testing (`import Testing`). Код ядра попадает в коммит только вместе с тестами.
- Компилятор и `make lint` — без предупреждений.
- Тексты интерфейса — по-русски; комментарии в коде — по-английски.
- Числа в интерфейсе — через `Formatting`: русская десятичная запятая при любом регионе Mac.
- Логи — `os.Logger` с subsystem `inco.mealplanner`.
- MCP-сервер пишет в stdout только протокол; диагностика — в stderr или `os.Logger`.

## Интерфейс и тема

- Тема тёмная: `AppDelegate` ставит `NSApp.appearance = .darkAqua` до первого кадра, поэтому тёмные и окна, и меню, и алерты, и Настройки.
- Цвета — только токены из `Assets.xcassets` через сгенерированные символы: `Color(.canvas)`, `Color(.textSecondary)`… Цветовых литералов в коде нет. Пока у каждого токена одно значение — тёмное; светлая тема добавит к тем же токенам светлый вариант.
- Токены: `Canvas` (фон окна), `Surface`, `SurfaceRaised`, `Card`, `Hairline`, `TextPrimary`, `TextSecondary`, `StatusInStock` / `StatusLow` / `StatusMissing`, `AccentColor`, цвета тегов `TagGray` … `TagRed` — палитра Notion для категорий и приёмов пищи (`TagColor.color`, `TagView`).
- Склейка `Text + Text` в macOS 26 устарела — стиль части строки задаём интерполяцией: `Text("\(Text("Отдел:").foregroundStyle(…)) \(value)")`.
- Перестановка перетаскиванием — `.draggable(id.uuidString)` и `.dropDestination(for: String.self)` на строке: `onMove` работает только в `List`.

## Единицы и КБЖУ

- У продукта есть основная единица (`BaseUnit`: г, мл или шт.) — в ней живут запасы и покупки. Пересчёт — `UnitProfile`: внутри массы и внутри объёма по таблице, иначе через граммы (вес штуки, плотность, вес именованных единиц вроде зубчика или пучка).
- Ложки и стакан — ровные метрические меры: ч. л. = 5 мл, ст. л. = 15 мл, стакан = 250 мл.
- Чего продукт не знает, того не угадываем: пересчёт возвращает `nil`, интерфейс показывает «?».
- КБЖУ хранится на 100 г. `NutritionTotal` складывает ингредиенты и считает, сколько из них удалось учесть. Диапазон «2–3» считается по середине; строки без количества («по вкусу») в полноту не входят.

## Рецепты

- Рецепт целиком — `RecipeDetails`: сам рецепт, строки ингредиентов, шаги, категории, приёмы пищи и продукты, на которые ссылаются строки. `save(_:)` записывает его целиком в одной транзакции: строки и шаги заменяются, пустые шаги отбрасываются. У строк и шагов id живут только в памяти.
- КБЖУ рецепта — `RecipeNutrition`: на 100 г по весу готового блюда, если он задан, иначе по сырым продуктам; на порцию — сумма, делённая на порции. Значения с сайта (`nutritionOverride`) заменяют расчёт. Неполный расчёт не обнуляется: списки показывают его с «≈», страница — «посчитано по N из M» и чего не хватило.
- `recipe_stats` — кеш для списков: КБЖУ, время, текст для поиска (название, шаги, заметки, продукты с синонимами). Его пересчитывает `RecipeDerived.refresh` в той же транзакции, что меняет рецепт или его продукт: сохранение рецепта, сохранение и объединение продукта. Любой новый способ записи, задевающий рецепт или продукт, обязан его вызвать.
- Продукт из рецепта удалить нельзя (внешний ключ `RESTRICT` и понятное сообщение); при объединении дублей строки рецептов переходят на оставшийся продукт.
- Корзина: `deletedAt`; списки и счётчики её не видят; при запуске удаляется то, что лежит дольше 30 дней, вместе с фото.
- Фото — `ImageStore`: JPEG до 1600 px по длинной стороне в папке `Images` рядом с базой; в базе только имя файла. У каждого рецепта своё фото (дубликат копирует файл); заменённое фото удаляется после сохранения, а файлы без рецепта старше часа — при запуске.
- Видео — `VideoEmbed`: YouTube (плеер youtube-nocookie), Rutube, VK Видео, любой `<iframe>`. Плеер грузится в WKWebView через `loadHTMLString` с https-адресом страницы: без него YouTube показывает «Ошибка 153». Ссылки — карточками LinkPresentation.
- Галерея: строка запроса — пара «категория — рецепт», поэтому рецепт из двух категорий виден в обеих; группы появляются по мере подгрузки; свёрнутые группы исключаются в SQL, но их счётчики остаются.

## Запасы и покупки

- Запас — `pantry_item`: количество в основной единице продукта; `NULL` — «есть, без счёта» (соль, специи), 0 — закончилось, строка остаётся. Отметка «заканчивается» — `isLow`, ставится руками и снимается покупкой.
- Наличие строки рецепта — `RecipeIngredient.availability`: staple и строки без количества смотрят только «есть или нет»; остальное сравнивается в основной единице, верхняя граница диапазона («2–3 зубчика» — три); не пересчитать — «?» (`unknown`). Необязательные строки не считаются.
- `recipe_stats.missingCount` — сколько строк не хватает на порции рецепта; его пересчитывает `RecipeDerived.refresh` при любой записи запасов, как и при правке рецепта и продукта. На нём фильтр «можно приготовить сейчас» (`maxMissing`) и сортировка по наличию.
- Покупки — `shopping_item`: продукт базы или текст, количество со своей единицей, причины («для»: рецепт и день) — JSON, фильтр по рецепту читает его через `json_each`. Добавление к позиции, ещё не купленной, суммирует количество через пересчёт единиц продукта; не складывается — отдельная строка; та же причина второй раз не добавляет ничего.
- Купленное: `checkedAt`; «в запасы» (`stockBought`) прибавляет количество в основной единице и убирает позицию, либо с «пополнять без вопросов» оставляет её купленной и отмечает `stockedAt`.
- Объединение дублей переносит запасы (с пересчётом единиц) и покупки; смена основной единицы продукта пересчитывает его запас, а то, что не пересчитать, становится «есть, без счёта».
- Поиск в запасах и покупках — по началу слов `searchText` продукта или текста позиции через `LIKE`: списки короткие, полнотекстовый индекс им не нужен.

## Меню на неделю

- Блюдо — `plan_entry`: день текстом («2026-10-23», `Day`, неделя с понедельника), приём пищи, рецепт или текст, порции, место в ячейке. Удаление приёма пищи удаляет его блюда, окончательное удаление рецепта — тоже.
- КБЖУ дня: на человека — по порции каждого блюда; всего — на все порции; в среднем — по дням, где что-то есть. Блюдо-текст и рецепт без КБЖУ дают «≈».
- Запасы распределяются по блюдам по порядку — день, приём пищи, место, — начиная с сегодняшнего дня; приготовленное уже своё взяло. Блюдо, на которое не хватит, помечается точкой; «Покупки на неделю» кладут всю нехватку в список с блюдом и днём в «для», второй раз — ничего (`WeekPlan.supply`, `addMenuShortages`).
- «Приготовлено» сначала показывает, что спишется (`cookingUse`: только посчитанные продукты, без staple), списывает подтверждённое и запоминает его в `used`; отмена возвращает ровно это. Дата готовки идёт в `recipe_stats.lastCookedAt` — сортировка «Давно не готовили».
- Перетаскивание: рецепт из списка — новое блюдо, блюдо — перенос, с ⌥ — копия; ⌫ убирает выбранные.

## Импорт по ссылке

- Без Claude: `RecipeImport` читает из HTML блоки `application/ld+json` и находит schema.org/Recipe — сам по себе, в массиве, в `@graph` или `mainEntity`; шаги — текст, `HowToStep`, `HowToSection`; время — ISO 8601; HTML-сущности и теги вычищаются. Окно `LinkImportSheet` сопоставляет строки с базой (`IngredientParser` и `matchProduct`): найден, один из нескольких, новый продукт с правкой названия.
- Страница без разметки уходит к Claude (`import_recipe`).

## «Напоминания» и «Поделиться»

- Синхронизация — `ShoppingSync`, раунд в обе стороны: при изменении списка покупок (через секунду тишины), по `EKEventStoreChanged` и при возвращении приложения на передний план. Включается в Настройках → «Напоминания»; доступ запрашивается при включении (`NSRemindersFullAccessUsageDescription`, entitlement `com.apple.security.personal-information.calendars`).
- Связь пункта и напоминания — `reminder_link` (что последний раунд записал: заголовок и отметку; разница показывает, какая сторона изменилась) и адрес `mealplanner://shopping/<id>` в напоминании (у Debug — `mealplanner-debug`). Все когда-либо связанные напоминания — в `reminder_known`: напоминание без пункта удаляется, даже если iCloud потерял адрес.
- Кто что решает: заголовок и заметку пишет приложение; отметку, удаление и новые пункты — телефон тоже. Количество, вписанное в заголовок на телефоне («Молоко — 2 л»), принимается. Пункт родных разбирается как строка ингредиента; если такой же ещё не куплен — прибавляется к нему, а лишнее напоминание удаляется.
- Отмеченное на телефоне становится купленным; с «пополнять без вопросов» сразу идёт в запасы, иначе ждёт «Убрать в запасы…».
- «Поделиться» — карточка шириной 390 pt в масштабе 3 (1170 px, ширина экрана телефона) и тот же рецепт текстом; QR-код ведёт на видео или источник.

## Поиск, фильтры и сортировка

- Запрос экрана — тип в `MealCore` (`ProductQuery`, `RecipeQuery`): текст, фильтры, сортировка. `MealStore` переводит его в SQL (`ProductListSQL`, `RecipeListSQL`); тот же запрос получат и MCP-инструменты.
- Поиск — FTS5-таблицы `product_ft` (по `product.searchText`) и `recipe_ft` (по `recipe_stats.searchText`). `searchText` и `nameKey` продукта пишет `ProductRecord` при каждом сохранении, поэтому имя и синонимы меняем только через него, а не сырым SQL.
- Запрос разбивается на основы слов (`SearchText.terms`: регистр и «ё» не важны, окончания режет стеммер Snowball), каждая ищется как префикс; все слова должны совпасть.
- При поиске полнотекстовая выборка — внешний цикл (`CROSS JOIN`): иначе SQLite повторяет её для каждой строки из индекса, и запрос с фильтрами замедляется в 30 раз.
- Порядок всегда заканчивается названием и id — равные значения не прыгают между блоками. Пустые значения — в конце при любом направлении.
- Списки грузятся блоками по 100 строк (`PagedList`): `ValueObservation` следит за `LIMIT n`, строка за 20 до конца загруженного добавляет следующий блок, новый запрос начинает с первого.

## Начальная база

- Каталог — `Tools/seed/catalog.py`: название, синонимы, отдел, источник КБЖУ (номер записи USDA FDC или типичные значения с упаковки), единицы. `make seed USDA=<папка с CSV SR Legacy>` собирает его в `Packages/MealKit/Sources/MealStore/Seed/SeedCatalog+Data.swift` — JSON внутри Swift-строки, потому что ресурсы SwiftPM недоступны MCP-утилите внутри приложения. Сгенерированный файл руками не правим.
- Значения USDA берём как опубликованы; калории проверяем по коэффициентам USDA для этого продукта, остальные — по 4·Б + 9·Ж + 4·У (`SeedCatalogTests`, тот же расчёт — в `build.py`).
- Начальная база — это миграция `seed: products 1`: загружается один раз, удалённое пользователем не возвращается. Новые продукты в базе — новая миграция только с ними.

## Разбор ингредиентов

- `IngredientParser` читает строки, как их пишут русские рецепты: количество (цифры, дроби, «½», диапазоны, «полтора», «пол-»), единица во всех формах, название, заметки в скобках, «по вкусу», «по желанию», «для жарки».
- Каждый новый случай — строка в `IngredientParserTests`; сейчас их 80.
- В редакторе рецепта строка ищет продукт по имени и синонимам; если такого нет — предлагает создать, и название можно поправить: в рецепте оно бывает в другом падеже («феты»).

## Хранилище и данные

- База — `AppDatabase` (GRDB): `~/Library/Application Support/inco.mealplanner/meals.sqlite`, у Debug — папка `inco.mealplanner.debug`. И приложение, и MCP-сервер пишут через `DatabasePool` (WAL) с ожиданием блокировки до 5 секунд.
- Схема меняется только новой миграцией в `AppDatabase.migrator`; уже применённые миграции не редактируем. Сейчас: `products`, `seed: products 1`, `recipes`, `pantry`, `planner`, `reminders`.
- Резервные копии — `Backups`: раз в день при запуске `VACUUM INTO` в `Backups/meals-ГГГГ-ММ-ДД.sqlite` рядом с базой (или в iCloud Drive, если так в Настройках), хранятся 14 последних. Фото не копируются.
- `AppDatabase.inMemory()` — пустая база для тестов (фото — во временной папке), `inMemory(seeded: true)` — с начальной базой.

## MCP

- Сервер `meal-planner` (`MealMCPServer`), транспорт stdio. Без аргументов внутри бандла работает с данными своего приложения (Debug — со своими); `--directory <папка>` — с указанной.
- Инструменты: `get_status` (не создаёт базу, если её ещё нет), `list_aisles`; продукты — `search_products`, `get_product`, `upsert_product`, `merge_products`; категории — `list_categories`, `create_category`, `update_category`, `delete_category`; рецепты — `search_recipes`, `get_recipe` (с наличием дома), `create_recipe`, `update_recipe`, `delete_recipe` (в корзину), `set_recipe_image`; запасы — `get_pantry`, `set_pantry`, `adjust_pantry`; покупки — `get_shopping_list`, `add_to_shopping_list` (в том числе нехватка для рецепта или меню недели), `check_shopping_items`, `remove_shopping_items`, `clear_checked`; меню — `get_week_plan`, `plan_meal`, `move_meal`, `remove_meal`, `mark_cooked` (без `confirm` только показывает, что спишется), `week_nutrition`. Промпты — `import_recipe`, `fill_recipe`, `fill_nutrition`, `what_to_cook`, `plan_week`, `migrate_from_notion`; их тексты и тексты кнопок «… с Claude» — одни и те же, в `ClaudeRequest`.
- Ответы — JSON со snake_case; ошибка вызова — `isError` и текст, по которому Claude может исправить вызов (`ToolError`, `StoreError`). Списки — `limit` (до 100) и `cursor` из `next_cursor` (это смещение).
- Ингредиенты в `create_recipe` и `update_recipe` — строка (разбирает `IngredientParser`, продукт должен быть в базе) или объект `{name | product_id, amount, amount_max, unit, note, optional, group}`. Продукт ищется `matchProduct`: точное имя или синоним, иначе поиск; из нескольких найденных берётся тот, чьё имя или синоним — те же слова («сахара» → «Сахар»). Если строка подходит к нескольким продуктам или строки нет в базе, не пишется ничего; новые продукты из объектов и новые категории создаются только после проверки всех строк, а при ошибке сохранения удаляются. Ответ называет `created_products`, `created_categories` и `matched_by_search`.
- Рецепт из Claude сохраняется одной транзакцией (`newRecipe(from:)`); `update_recipe` меняет только переданные поля, `unset` очищает поля, фото по `image_url` скачивается до записи, и рецепт сохраняется, даже если фото не скачалось (`image_problem`).
- После каждой записи сервер шлёт Darwin-уведомление `inco.mealplanner.changed` (`ExternalChanges`); приложение вызывает `notifyExternalChanges()`, и его `ValueObservation` перечитывают данные. При возвращении приложения на передний план сверяется `PRAGMA data_version` — на случай пропущенного уведомления.
- Новый инструмент: определение в одном из массивов `MealTools.all`, ветка в `MealTools.call` (запись отмечается как изменение), тесты в `MealMCPTests` (`ToolFixture` — сервер над временной папкой с начальной базой). `PackagingTests` проверяет, что встроенный в бандл сервер отвечает по stdio.

## Claude в приложении

- Настройки → Claude: сервер в `claude_desktop_config.json` (прежний файл сохраняется рядом с датой), фрагмент для ручного добавления и команда для Claude Code в терминале. У Debug — сервер `meal-planner-debug`, со своими данными.
- Кнопки «… с Claude» (импорт по ссылке, дозаполнить рецепт, КБЖУ продуктов, перенос из Notion) идут через `AppModel.askClaude`: без подключённого сервера приложение сначала предлагает подключить. Дальше — `ClaudeHandoff`: новая сессия Claude Code в папке `Meal Planner` внутри папки данных (ссылка `claude://code/new`) или новый чат с запросом в буфере обмена.
- В папке `Meal Planner` — только CLAUDE.md (`ClaudeWorkspace.instructions`). Файл, который пользователь поменял, не трогаем. Меняя текст, добавьте SHA-256 прежнего текста в `ClaudeWorkspace.earlierDefaults` — тогда нетронутые копии обновятся.
